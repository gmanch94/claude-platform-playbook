Claude Platform Playbook

Claude Code Managed-Controls Builder As of 2026-07

Answer six posture questions; get the deployable bundle for your delivery mechanism — managed-settings.json, the delivery wrapper, a managed CLAUDE.md, and a filled operator checklist. Every field is traceable to a section of claude-code-enterprise-config.md; this tool composes that content, it doesn't add claims. Mechanics verified [H] against permissions + sandboxing, 2026-07-25.
Why a generator and not copy-paste. Managed security fields fail closed: a malformed forceLoginOrgUUID blocks every login, a typo in allowedMcpServers admits zero servers. So this tool never emits a placeholder — an unsupplied key is omitted, and export is blocked until the blockers below are clear. It also refuses rule sets that cannot work: precedence is deny → ask → allow, first match wins, and specificity does not reorder, so a broad deny silently kills a narrower allow. That collision is invisible in a hand-written file and is the first thing the linter checks. Runs entirely in your browser — no network calls, nothing transmitted.

Left blank, each key is omitted entirely — never written as a placeholder. Blank required values block export.

Both parts, or the key is omitted. A typo'd allowlist admits zero, not all.
Comma-separated hostnames only — no scheme, no path (github.com, not https://github.com/). A leading *. is allowed. This governs what sandboxed Bash commands can reach; too tight blocks package installs, so stage on a canary.
Hostnames only — there is no IP or CIDR primitive. A range (10.0.0.0/8) is not expressible here; ranges belong to your proxy or firewall (config §5.3). What this is good for: named internal hosts. deniedDomains outranks allowedDomains when both match and merges from every settings scope regardless of allowManagedDomainsOnly — so unlike your allowlist (which appears at the Hardened tier), a developer's own settings file cannot append its way around it. Named hosts only, and note this generalizes poorly across clouds: GCP exposes metadata.google.internal, but AWS and Azure instance metadata is reached at the link-local address 169.254.169.254 — and whether a bare IP literal matches a domain pattern is not documented, so on those clouds the metadata endpoint is a proxy or firewall rule, not an entry here. If your cloud publishes a hostname alias, verify it before relying on it. Good candidates for this field: an internal admin domain, *.corp.example.com, a management console host.
Unset means Claude runs its own proxy, which allows on the client-supplied hostname without inspecting TLS — the docs' own warning is that a broad allow entry is then an exfiltration path (domain fronting). If containment is the requirement, point the sandbox at a proxy you control, terminate TLS there, and install its CA inside the sandbox. Note this is the sandbox's own proxy, which does take SOCKS5 — not the client-level HTTPS_PROXY path, where SOCKS is not supported (config §5.3). Two different proxies. On macOS that breaks TLS verification for Go-based tools (gh, gcloud, terraform) until you also tick enableWeakerNetworkIsolation below — which itself opens an exfiltration path. Both costs are real; pick knowingly.

3Assets to protect

Deny rules are generated from what you actually run, not a generic list. Each ticked asset becomes a row in the coverage matrix — with its gaps visible.
Anchors matter. These emit the // filesystem-root form, so the rule holds wherever a session starts. The narrower Read(.env) covers only at-or-under the launch directory — not a parent, not another checkout. The global form also covers scratch dirs and node_modules fixtures; if that friction is what gets your policy disabled, narrow it deliberately and record the gap.

4Actions to gate

These go in ask, not deny — a deny on git push breaks legitimate work and gets the whole policy switched off. Tiered by can it be undone quietly?
Also emitted, always, so you can review it here rather than discover it in the JSON: Bash(curl *), Bash(wget *), Bash(nc *), Bash(ssh *) are added to deny. That is the docs' own remedy for argument-constrained network rules being fragile — but an org-wide ssh deny surprises people, so it is stated up front. If your engineers need ssh from a Claude session, move it to the ask list by hand after export and record why.
Advanced — additional managed-settings fields (not the full set)
Merge your existing rules — and lint them
Paste rules you already run, one per line, prefixed deny:, ask:, or allow:. They are merged into the output and put through the full linter — which is the only way checks 1–5 (deny-shadows-allow, bare-name removal, word boundary, unanchored allow globs, display-label tool names) can fire, since the generated rules are correct by construction. If you have an existing policy, this is where the collisions surface.

Coverage matrix

Asset × surface × what enforces it. An empty cell is a known gap, not an oversight — that's the point of showing it. Deny rules never reach arbitrary subprocess I/O or environment variables; only the sandbox does.
