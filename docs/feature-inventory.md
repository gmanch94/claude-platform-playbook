### How to use the `Used in artifacts` column (added 2026-07-24)

Until now the Models table was the **only** inventory section without this column — so a model change had no mechanical propagation path and dependents were found by hand. That's what let a self-contradicting guide ship during the Opus 5 sweep (see [`../LESSONS_LEARNED.md`](../LESSONS_LEARNED.md) 2026-07-24). A model release is now a grep, not an archaeology dig. Two halves — **do both**:

**1. The tier-pin set — mechanical.** These carry the boilerplate current-tier line (`Opus 5 / Sonnet 5 / Haiku 4.5`) and usually need nothing but the swap. The per-model columns above deliberately *omit* these to stay readable:

> `adoption-playbook` · `agentic-threat-model` · `anti-use-cases` · `claude-code-101` · `claude-code-adoption-guide` · `claude-code-starter-skills` · `claude-misconceptions` · `data-advisory` · `decision-spine` · `eval-starter-pack` · `governance-overlay` · `hooks-starter-pack` · `incident-response-runbook` · `mcp-starter-pack` · `model-selection-guide` · `multi-agent-patterns` · `README`
>
> Regenerate rather than trusting this list — the pattern must be **order-agnostic**, because not every file writes the tier Opus-first (`README` reads `Haiku 4.5 / Sonnet 5 / Opus 5`):
>
> ```
> grep -rlE "(Opus|Sonnet|Haiku) [0-9.]+ ?[/·] ?(Opus|Sonnet|Haiku) [0-9.]+" artifacts README.md
> ```
>
> An Opus-first-only pattern silently returns 16 of 17 and looks clean — the same half-updated-guard failure logged for `/stale-check`. Verify the count matches before trusting the output.

**2. The per-model columns — judgment.** Rows tagged *(historical)* or *(mostly historical/comparison)* cite a **superseded** model on purpose — version history, cache-floor and context-window comparisons, price anchors, migration examples. **Verify before flipping any of these**; blanket-replacing them destroys the comparison that makes the artifact useful. Only current-state pins move.

**The half that isn't a grep.** After the swap, re-read the substantive dependents for **advice written against the old model's defaults** — that's what the column can't find, and it's what ships broken (2026-07: a guide's "thinking: default off" rule survived a clean label sweep and contradicted its own new header). Behavioral contract to diff each release: thinking/effort defaults · newly-invalid parameter *combinations* · cache floor · context/output ceilings · tokenizer · **capability and service-tier regressions** (Opus 5 dropped web fetch and Priority Tier support).

**Opus 5 launch rows (added 2026-07-24, [H] live-verified against anthropic.com/news/claude-opus-5 + the linked platform docs)** — two betas shipped *alongside* the model, both decision-relevant and neither a model-table edit. **Mid-conversation tool changes**: previously, changing the tool set mid-conversation invalidated the prompt cache and forced a re-write of the cached prefix — a real cost + latency tax on long agentic loops and on multi-agent patterns that hand different tool sets to different phases. This removes that tax; it changes the caching economics of tool-swapping agents, so re-check any design that was contorted to keep the tool list frozen. **Automatic fallbacks**: server-side routing so a request the safety classifiers flag on Opus 5 / Fable 5 goes to another model instead of returning blocked. **Read the default carefully — it is not uniform:** in **claude.ai, Claude Code, and Claude Cowork this is ON by default** and flagged requests fall back to **Opus 4.8**; on the **API it is opt-in**. So for the three product surfaces this repo covers in depth, the reader's action item is **not** "decide whether to enable it" but "know it is already happening." Decision impact both ways — it raises effective availability (fewer hard-blocked requests), *and* it means *a request can be served by a model you didn't select*, which undercuts eval reproducibility, model-pinned audit evidence, and per-model cost attribution. Both **beta** — do not pin production SLAs. **Used-in is deliberately narrow:** each row lists only the artifacts that *actually cite it today* — mid-conversation tool changes in [`../artifacts/multi-agent-patterns.md`](../artifacts/multi-agent-patterns.md) (phase-scoped tool sets no longer pay a cache-rebuild penalty) and automatic fallbacks in [`../artifacts/agentic-threat-model.md`](../artifacts/agentic-threat-model.md) (a sixth pre-ship question: do you know which model actually served the request?). **Forward-looking, not yet wired:** `cost-calculator` (cache economics of tool-swapping agents), `incident-response-runbook` (blocked-request incident class). Wire those citations when each artifact adds the section — don't list an artifact here before it cites the row.

| Floor | Models |
|---|---|
| **512 tokens** | **Opus 5**, Fable 5, Mythos 5 |
| 1,024 tokens | Opus 4.8, **Sonnet 5**, Sonnet 4.6, Sonnet 4.5 |

**Opus 5 halved the floor to 512** (from 1,024 on Opus 4.8) — a real cost lever: prompts previously too short to cache now create cache entries **with no code changes**. **Tokenizer** — Claude 4.7 and later models (incl. Opus 5, Sonnet 5) use a newer tokenizer. **Reconciling the two figures this file carries:** the pricing doc states **~30% more tokens for the same text**, and the migration guide gives the range **~1.0–1.35× (up to ~35%)** — same phenomenon, one quoted as a typical value and one as a range, both [H] verified 2026-07-24. Use ~1.0–1.35× when sizing a specific workload and ~30% as the planning rule of thumb; the exact figure depends on content and workload shape. Sonnet 4.6 and earlier use the previous tokenizer. Budget the **effective** cost, not the sticker rate.

**Extended thinking note** — **Opus 5 changed the default; see the thinking-default note directly below.** Opus 4.7 and 4.8 support **adaptive thinking only**: `thinking: {"type": "adaptive"}` plus the `effort` parameter to control depth. Setting `thinking: {"type": "enabled", "budget_tokens": N}` returns HTTP 400. They also reject non-default `temperature` / `top_p` / `top_k` (400). Opus 4.6 and earlier: manual `budget_tokens` still works but adaptive is recommended.

**Thinking-default change on Opus 5 (breaking — migration-relevant).** On Opus 4.8 a request runs **without** thinking unless you set `thinking: {"type": "adaptive"}`. On **Opus 5 the same request runs WITH thinking on** — the model decides when and how much to think per turn, and `effort` is the depth control. The wire value is unchanged (`adaptive` stays valid, equivalent to the default). **Consequence to budget for:** `max_tokens` is a hard limit on *total* output (thinking + response text), so **revisit `max_tokens` for any workload that ran thinking-less on 4.8** — otherwise responses can truncate. **The API keeps an option to disable thinking, but only at effort `high` or below** — `thinking: {"type":"disabled"}` combined with `xhigh` or `max` **returns a 400 error**, validated on *every* request (so a mid-conversation effort bump is rejected even if earlier turns passed). This is an explicit breaking change from Opus 4.8. [H — verified 2026-07-24] Effort ladder: `low` / `medium` / `high` (default) / `xhigh` / `max`; at `xhigh`/`max` set a large `max_tokens`. Opus 5 converts effort into quality more reliably than earlier Opus models — `low`/`medium` deliver strong quality at a fraction of tokens + latency, so effort is now a real cost lever, not just a quality dial. Source: platform.claude.com/docs/en/about-claude/models/whats-new-opus-5 (verified 2026-07-24).

**Fast mode (Opus 5, and Opus 4.8)** — **still a research preview** ([H] verified 2026-07-24: pricing doc reads "Fast mode, in research preview, provides significantly faster output for Claude Opus 5 and Claude Opus 4.8") — **do not pin production SLAs to it.** On Opus 5 it runs **~2.5× default speed at 2× base price** ($10/$50 per MTok), via `speed: "fast"` + the `fast-mode-2026-02-01` beta header, and through **usage credits** in Claude Code. **Claude API only — NOT available on Amazon Bedrock, Google Cloud, or Microsoft Foundry**, so it is not a lever for hyperscaler-procured orgs. Not available with the Batch API. **Routing collision worth pricing deliberately:** Opus-5-Fast at 2× base lands at **$10/$50 per MTok — exactly Fable 5's rate**. So at that budget the real question is *speed vs. frontier reasoning*: same $/token buys either ~2.5× faster Opus 5 or Fable 5's deeper reasoning. Latency-bound interactive work argues for Fast; hardest-reasoning batch work argues for Fable. Don't let the frontier-reasoning preset and a Fast-mode rollout compete for the same budget line unpriced. Doc anchor: anthropic.com/news/claude-opus-5 (verified 2026-07-24). Opus 4.8's Fast mode was a research preview.
